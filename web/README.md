# `@lancedb/lancedb-web`

Read-only WASM search client for HTTP-hosted Lance tables.

## What it does

`@lancedb/lancedb-web` opens a published Lance table over HTTP, reads Arrow IPC results,
and executes browser-side search against the published manifest and data files.

```ts
import { openTable } from "@lancedb/lancedb-web";

const table = await openTable("https://example.com/my_table.lance");
const schema = await table.schema();
const results = await table.search({
  vector: [0.1, 0.2, 0.3],
});

table.close();
```

## Runtime notes

- The package is read-only. It supports `schema`, `search`, `refresh`, and `close` only.
- The table must be reachable over HTTP(S) and include the published sidecars generated by
  LanceDB web publishing (`_web.json`, `_snapshot.json`, `_latest.manifest`, `_latest.version`).
- The default path prefers a Web Worker when available. Passing a custom `fetch` forces the
  direct runtime path so the WASM data plane can use that fetch implementation consistently.
- In non-browser runtimes, pass `OpenTableOptions.fetch` unless `globalThis.fetch` is already
  available.

## Intentional browser limitations

- The browser path is optimized for published, read-only tables. It is not a general remote
  execution engine and does not support writes.
- Text search is constrained to the published FTS columns, but scoring happens client-side and
  may not exactly match native/server-side FTS ranking.
- Browser-side vector ranking currently supports `l2`, `cosine`, and `dot`. `hamming` is not
  supported in the browser execution path.
- Performance is best for smaller published tables and search-oriented snapshots. Large-table
  browser queries still depend on HTTP range reads and local ranking work.
